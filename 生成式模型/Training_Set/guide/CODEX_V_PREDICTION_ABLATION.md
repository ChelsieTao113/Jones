> 请完成代码实现、必要检查、实际训练、完整采样评价和中文报告，不要只输出计划。本轮用相同模型和训练预算比较两种预测方式，检验 v_prediction 是否改善高噪声恢复与纯噪声生成。用户已授权本文件范围内的小规模实验；完成后停止，不自动启动全量训练。

## 1. 研究问题与结论边界

目前已观察到：模型对“真实 GS 矩阵加中低噪声”的恢复尚可，但在高噪声下失败；纯噪声生成的原始矩阵幅值过大，最终投影后仍不成像。

原 epsilon 方式恢复干净矩阵时，高噪声会放大噪声预测误差。本轮把网络训练目标改为 v，检验改变预测方式能否带来实际改善。

**v_prediction 不是新网络架构，也不是只换采样参数。** 训练标签、训练损失、预测值解读和采样器 prediction_type 必须配套修改，必须重新训练。

本轮只比较：

| 新实验名称 | 网络预测目标 | 训练损失 |
| --- | --- | --- |
| E | epsilon，实际加入的噪声 | 普通无权重 MSE |
| V | v，按第5节计算 | 普通无权重 MSE |

不得沿用上一轮 A/B 名称混淆：旧 A 是 epsilon 基线，旧 B 是 epsilon＋物理损失。旧结果只作历史参照。本轮 E/V 都不加入成像、功率、酉约束或其他辅助训练损失，物理计算继续用于评价。

更换预测量也会改变不同噪声档在等效干净矩阵误差中的权重。因此，本轮比较的是完整的“预测目标＋对应普通MSE”方案，不能声称已单独区分数值公式与等效损失加权的贡献。

## 5. 精确数学定义与实现

设 `a = sqrt(alphas_cumprod[t])`，`b = sqrt(1-alphas_cumprod[t])`；a、b广播为[B,1,1,1]。x0为原始六通道矩阵，epsilon是标准高斯噪声。

共同的前向加噪：

```python
xt = a * x0 + b * epsilon
```

### 5.1 E组

```python
target = epsilon
pred = unet(xt, t, encoder_hidden_states=condition_tokens).sample
loss = mean((pred - target) ** 2)
pred_x0 = (xt - b * pred) / a
```

### 5.2 V组

```python
target_v = a * epsilon - b * x0
pred_v = unet(xt, t, encoder_hidden_states=condition_tokens).sample
loss = mean((pred_v - target_v) ** 2)
pred_x0 = a * xt - b * pred_v
pred_epsilon = b * xt + a * pred_v
```

V的训练目标优先调用已安装训练scheduler的 `get_velocity(x0, epsilon, t)`；与显式公式核对一致。如果该版本API有差异，查阅本地实现并使用等价公式，记录依据。

- V的训练scheduler与推理scheduler都保存 `prediction_type='v_prediction'`。
- E对应 `prediction_type='epsilon'`。
- 采样时直接将网络原始输出交给与组别匹配的 scheduler.step。V组不要先转换成epsilon再交给仍配置为v的scheduler，避免重复转换。
- 下一步输入使用返回的 prev_sample；pred_original_sample仅用于观察。
- 不给网络输出增加tanh、clamp或每样本归一化。
- 不根据预测值重标定矩阵总功率。
- 当前公式的x0是六通道真实矩阵，不是目标图T，也不是带噪xt。
- loss必须对原batch/通道/像素按原方式平均，再正确进行梯度累积，不能重复除以累积次数。

### 5.3 为什么这样改，以及不能怎样解释

固定xt时，epsilon预测误差引起的x0误差系数为 b/a；v预测误差引起的x0误差系数为 b。后者不会出现除以很小a的放大。

但两个网络预测目标不同，误差分布和学习难度也不同。因此不能将E组训练MSE与V组训练MSE直接比较后宣布胜负，必须比较共同的x0恢复和最终成像。

v方式也可能预测接近零或过度平滑的矩阵，单凭幅值下降不能认定成功。

## 6. 只做与本次变化有关的必要检查

### 6.1 公式和scheduler检查

用真实x0和固定epsilon，在t=[55,188,495,802,935,990,999]上验证：

1. get_velocity与显式v公式一致。
2. 真实v代入恢复x0/epsilon公式可恢复原值。
3. E、V的betas、alphas_cumprod和实际100步采样列表完全一致；输出配置差异应只包含本任务允许项。
4. 在同一xt及选定合法采样t下，给E scheduler真实epsilon、给V scheduler真实v，比较pred_original_sample和prev_sample。分别创建/重置scheduler，避免状态交叉。中低噪声应接近；高噪声epsilon反解可能有浮点误差，单独解释。
5. 不能只在t=0检查，否则难以发现v符号或时间步广播错误。

建议公式检查用float64验证数学关系，再用实际float32记录误差。float32中低噪声x0相对误差目标≤1e-5；高噪声epsilon误差放大不机械按同一阈值判失败。异常必须具体定位，不随意放宽所有容差。

### 6.2 模型实际训练检查

两组从相同随机初始模型/编码器权重分别执行20次smoke更新：

- 前向、loss、梯度、参数变化均有限，U-Net和条件编码器确实更新。
- 保存/恢复一次，核对模型、编码器、优化器、随机状态及prediction_type；恢复后不会把V误当epsilon。
- 做一次完整生成只检查形状与有限性，不要求smoke阶段成像。

smoke权重不得作为正式某一组的起点。正式训练重新创建共同的随机初始状态。

### 6.3 旧行为回归

新代码设置epsilon时，在固定输入、随机状态和优化器条件下与旧epsilon更新一致至原浮点容差。诊断/绘图不能改变训练随机流。

如果发现共同程序bug，修复后两组使用同一修复，并明确区分修复与v方式的收益。

## 9. 共同评价指标与防止虚假改善

最终主成绩全部取合法投影后矩阵，并同时保存raw用于诊断：

| 指标 | 汇总方式 |
| --- | --- |
| PCC | 每通道；每任务取最低通道，再统计6种子中位数 |
| e_abs | 每通道；每任务取最大通道，再统计6种子中位数 |
| ROI功率 | 实际份额、相对beta误差；每任务最大相对误差 |
| 背景漏光 | 沿用原定义；每任务最差值 |
| 合格率 | 原三通道同时满足全部门槛 |
| 矩阵合法性 | 对称/酉残差；raw奇异值分位数 |
| 投影改变量 | Frobenius相对变化量，分母保护并记录 |

原门槛参考：PCC≥0.90、e_abs≤0.10、ROI功率相对误差≤0.20、背景漏光≤0.15、对称/酉残差≤1e-4，必须核对实际代码，不能静默修改。

同时检查：

1. V是否只是让输出接近零？记录raw Frobenius范数、奇异值分位数、近零像素比例（阈值与尺度记录）。raw接近零时投影可能产生任意方向，不能只看合法性通过。
2. 是否数值不爆了，但图案相关性仍接近零？应称“幅值改善，成像未解决”。
3. 是否图案变好了但功率或背景变差？必须报告取舍。
4. 是否只有已知答案加噪恢复改善，纯噪声完整生成没有改善？不能称已学会生成。
5. 所有展示保留理想T和GS标签成像两个参照；不得把GS图替换理想目标。
6. 两组MSE数值不可直接排胜负；同一步数/同任务/同生成噪声的物理指标才是主对比。

## 10. 预先确定的判断规则

第一对的最终6个配对生成种子满足以下任一条，才进入两个额外训练种子的复核：

### 路径A：已有较明确的相对改善

- projected最差通道e_abs中位数至少降低20%；
- projected最差通道PCC中位数至少增加0.10；
- 至少4/6配对生成结果的最差通道e_abs改善；
- ROI相对功率误差与背景漏光中位数各自不增加超过0.02（绝对量）；
- 矩阵合法性、有限性均通过。

### 路径B：达到实际合格

- V至少4/6生成结果达到原全部门槛，且合格数高于E；
- 无数值异常，未更改合格线。

这是控制实验规模的工程筛选规则，不是统计显著性检验。若两组都已经达到高合格率但V不占优，应报告“基线也已可用，本轮未证明V有优势”，不强行继续重复。

若启动3个训练种子复核，逐种子列出结果，不把18张生成图当18次独立训练。至少2/3训练种子方向一致才能称“初步可重复的改善”；单任务结果仍不能证明泛化。

如果误差下降但仍0合格，必须写“有所改善，尚不能正式训练”，不能用相对进步替代实际质量。

建议命令形态如下，必须按实际实现写成能运行的命令，不要把占位命令冒充已经执行：

```text

conda run -n metasurface python <实际入口> --run-paired --train-seed 20261124
conda run -n metasurface python <实际入口> --evaluate
conda run -n metasurface python <实际入口> --report
```

主报告至少包含：

- 是否改善、是否达到原合格线、证据限于几对训练模型。
- E/V最终同一任务的6种子逐项表及中位数，不只写平均loss。
- t=990高噪声恢复如何变化；自由生成早期幅值是否改善并持续到末步。
- 改善是否只出现在幅值，还是三张图都更接近目标。
- 有无近零输出、严重投影改动或能量取舍。
- 所有实际改动、任何程序bug修复、未完成步骤和停止原因。
- 下一步只提出一项有证据支持的优先实验，不自动执行。

图像使用三通道分行，至少含理想目标、GS、E最终projected、V最终projected；raw可另列。绝对强度与仅看形状的归一化图明确标识，数字功率必须保留。包含所有6种子的接触表或索引，不能只挑最好图。
